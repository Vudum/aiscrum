What happens in a meeting

  1. 1You speak. The browser turns your voice into text and sends it to the app server.
  2. 4Meeting ends. The app server hands the board changes to its MCP client.
  3. 2App server picks who answers and asks that AI teammate for one line.
  4. 5MCP client asks the MCP server to run a tool, e.g. add_to_sprint.
  5. 3The teammate's line comes back and your browser says it out loud.
  6. 6MCP server makes the change and saves it in the project file.
  8. 7You see it in the board, charts and demo.
Two different servers: the app server is Scrum Gym itself (Flask) and runs the meetings. The MCP server is a small separate program that owns the board. The app's MCP client asks it to make changes.
Steps 1–3 repeat for every turn. Steps 4–7 happen once, when the meeting closes. No API key? Teammates read scripted lines.
